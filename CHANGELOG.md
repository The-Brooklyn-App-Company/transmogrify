Acceptance exception (2026-11-24): fresh-machine and live-operations checks
remain unproven and are accepted for this release only. The bounded scope
and retained checks are recorded in [ROADMAP](ROADMAP.md#release-gate-and-recorded-exceptions).

- **Evidence and time provenance** (K-10, K-12): current-state reports
  distinguish observations from inferences and name their basis. Plans and
  configuration do not prove use. Absence claims name the searched scope.
  Observation timestamps come from a clock reading already seen or a
  timestamp generated by the writing script, never an estimate or
  prediction. Planned dates and quoted historical times retain their source.
- **Smaller changes, bounded review** (K-09, K-20): reuse existing
  mechanisms and explain new ones before building. Independent review stops
  after a clean round or two rounds; reaching the cap is not clearance.
  Unresolved high-severity findings go to the owner; lower-severity findings
  need an owner and reference. Guides and the review handoff skill follow
  the same rule.
- These are source guidance updates. Upgrading a kit pin does not change
  client approval settings, hooks, schedules or services, and source
  publication does not establish installation or adoption.
- **Installed documentation stands alone:** the optional website-source
  and worked-grants-example links open their canonical public source files.
  They no longer point into website or test trees omitted from the install.
  The fresh-install regression checks those references in both installed
  copies using the shipped link checker.

- **Leak guard and its timeout regression** (K-31, K-25): L03 exempts only
  the candidate inside an explicitly labelled integrity-hash payload with
  the stated algorithm's digest length and canonical base64 padding.
  Hash words elsewhere on a line and unlabelled runs containing `+` or `=`
  no longer hide URL/path identifiers. Unlabelled encoded text with an
  identifier-shaped fragment is checked normally; a reviewed false positive
  can use the existing `leak-ok: L03` marker. The test guard now gives its
  command an owned process tree and stops nested groups on timeout under
  either shell. Timeout fixtures self-expire if cleanup regresses.

### Known issues

- **Integrity context:** a URL or path that has the exact length and
  alphabet of a digest can still be mistaken for an integrity value. The
  scanner does not yet require explicit integrity-field context.
- **Timeout ownership:** the test guard covers the blocking fixture tree
  it starts. Descendants that daemonize into another session or are
  reparented before cleanup can escape it; it is not a general process
  manager.
- **Timeout PID identity:** cleanup assumes parents keep their children
  waitable. Ignoring `SIGCHLD` can let the kernel reap a child despite its
  stopped parent, invalidating that assumption. No signal to an unrelated
  process was reproduced. Keep the guard confined to controlled fixtures.

## 2.0.0

Released 2026-11-20, on the owner's decision under the dated exception in
ROADMAP.md (no pass yet on a machine that has never run either layer).

Transmogrify is now an operating system for a small team of long-running AI
agents on your own always-on Mac, across Claude Code and Codex: the Agent
Operations kit (0.3.1) joins the worker-lane skill (0.6.2) as one project,
one install and one first run. Scope: Claude Code and Codex, macOS first,
Linux best effort for the `sh` layer; Antigravity is on the roadmap.

- **One project for both layers.** The kit is imported with its history
  (`git subtree` under `ops/`, no squash): the rules in `kit/KIT.md` keep
  their IDs, the kit's docs move to `docs/operations/`, its POSIX sh tools
  to `ops/`, its skills beside `SKILL.md` in `skills/`, and its sh and dash
  suite to `test/ops/`, which CI runs as its own job with `shellcheck` and
  `check.sh kit`. The rules file's byte budget is 11100 bytes.
- **One install, pinned.** `./install.sh` (and the start prompt) copies
  `ops/`, `kit/` and `skills/` with the worker tools, from a release tag or
  the pinned release commit; one version for both layers (`package.json`).
- **One first run.** `doctor.js --operations` adds the operations layer's
  read-only host checks as non-blocking owner actions; `setup.js
  --apply-host` applies them on consent; `bootstrap.sh` stays the sh entry
  point and now also offers to write the grants (below).
- **Approvals that follow an operator** (`ops/grants.sh`, new). One
  client-neutral grants file in the Oracle home, rendered into Claude
  Code's `autoMode.allow` (tagged entries only, every other byte kept) and a
  managed `[auto_review]` block in each home's own `.codex/config.toml`
  (the Oracle home's too, for grants marked for Codex), read back through
  `codex app-server` and rolled back on failure; a three-state check
  (rendered, resolved, accepted) run nightly, by the first run and by
  `switch.sh`, which refuses a switch until the target side matches. The
  first run writes client settings only after a consent step: a yes at the
  terminal, or an explicit `--yes`. Never run against a real client config
  yet.
- **Every first-run step is guided and checked.** `bootstrap.sh` writes the
  Codex recovery hook (`~/.codex/hooks.json`) on consent, prints the exact
  steps to trust it in the interactive Codex CLI (the desktop app's
  composer has no `/hooks`), waits, asks Codex itself (`codex app-server`
  `hooks/list`: enabled and trusted at the hook's current hash, from
  `hooks.json` or `config.toml`), and confirms with one isolated read-only
  `codex exec` run (plugins, apps and tool servers off, failing closed)
  that the digest arrives; the pass is bound to the hook's hash. The Claude
  hook is checked by parsing the settings JSON (`hooks.SessionStart`), with
  the exact JSON printed when missing. Generated commands are shell-quoted. The Codex CLI is found from the
  profile's new `codex_cli`, `PATH` or a desktop app bundle, and used only
  if it answers `--version`. Sign-in is read from `claude auth status` and
  `codex login status`; the app restart after the App Nap write from each
  app's process start time (install.sh now records when it wrote App Nap);
  Codex pins from the app's own pinned list (an undocumented state file,
  read only). Marks remain only where a check cannot run, and for the
  Claude sidebar, which nothing on disk shows.
- **The profile's `path` finds the CLIs.** It replaces `PATH` for every kit
  script, and the example profiles left out `~/.local/bin`, where Claude
  Code's native installer puts `claude`, so the checklist said "no Claude
  CLI answered" and kit jobs could not start it. `bootstrap.sh` step 2 now
  appends the folders of `claude` and `codex` (and `~/.local/bin` when
  `claude` is there but not on `PATH`) to the profile's `path` when missing.
  Found in the live first run.
- **Locks that hold on every host.** Directory locks (the lease lock and
  guard, the `mkdir` fallback of `ao_lock`, forwarding marks) are claimed
  with an exclusive file inside the new directory, since uutils coreutils'
  `mkdir` (Ubuntu 26.04's default) can report success after losing a race;
  the descriptor of a kernel lock is closed inside each background subshell,
  since dash keeps a saved copy of a redirected descriptor open there; and
  the portable timeout watchdog (hosts without `timeout`) no longer holds
  the lock. Found by the first CI runs on hosted runners.
- **Leak guard** (`ops/check.sh leaks`). Nothing owner- or
  company-specific reaches the public tree: generic rules (home folders,
  e-mail addresses other than the project contact, Slack ids, API-key
  shapes, Keychain item names) over every tracked file and every staged
  copy, plus an optional private denylist (`TRANSMOGRIFY_LEAK_DENYLIST` or
  the profile's `leak_denylist`) that must live outside the repository and
  is never quoted: output is `file:line: RULE` only, with one stderr line of
  denylist counts; `--require-denylist` fails without one. It runs in CI
  (generic rules), in the pre-commit hook `install.sh precommit` installs
  (`--denylist FILE --require-denylist` for a maintainer's checkout), and
  first in the release checklist.
- **K-30: agents act as the authorized user.** Commits, pull requests,
  comments and messages made on the human's authority carry no agent or
  model tag, trailer or signature unless the profile sets
  `attribution=disclose`. Worker lanes now follow it: the exchange preamble
  tells a child to add no attribution, and `harvest --commit` adds no
  `Co-Authored-By` trailer, unless `attribution=disclose` (or
  `TRANSMOGRIFY_ATTRIBUTION=disclose`) is set. Claude children launch with
  Claude Code's own `attribution` and `includeCoAuthoredBy` switches off,
  and the first run sets the same in the Claude settings file on consent
  (checklist row `attribution`). Finish any pending `harvest --commit`
  before changing the setting: a resumed harvest recomputes its commit
  message and refuses a mismatch.
- **Worker completions through the mailroom**, behind
  `TRANSMOGRIFY_COMPLETION_ROUTE=mailroom`: a child's wake becomes a note in
  its parent's inbox. The default is unchanged until a live proof.
- **`lane.sh` is now `switch.sh`.** Moving an operator between apps is a
  switch; "lane" means only a worker lane. `ops/lane.sh` stays for 2.0.x as
  a deprecated alias (same arguments, one warning) and is removed in 2.1.
  The switch's inbox notes are named `switch-out`, `switch-in` and
  `switched`.
- **K-11: done is end to end.** Done means the whole user-visible behavior
  works in a staging or real environment, shown by a walk with screenshots;
  every build is scoped by the user surfaces it touches. The operator home
  template gains a build checklist and the delegation packet's acceptance
  criteria start and end with those two steps.
- **The operations layer speaks as Transmogrify:** new homes cite the
  "Transmogrify operations kit"; `status.sh --drift` still reads homes that
  cite the "Agent Operations kit".
- **No Apple Events on read paths.** The doctor finds the ChatGPT desktop
  app from its standard locations and then Spotlight (`mdfind`), never
  through `osascript`; the consented relaunch quit is the only Apple Events
  call left, and a test keeps it that way.
- **Byte-exact renders and safer host apply** (review fixes): the grants
  renderers keep every byte outside what they manage (formatting, escapes,
  CRLF line endings); host backups of the two bridges' duty files no longer
  share a name; routine commits take only their own paths and leave other
  staged work alone.
- A new README, one skill index (`skills/README.md`), and a guide for a
  second person adopting on their own machine
  (`docs/operations/adopting.md`).
- **The website, rebuilt for 2.0** from `site/site-content.md`, hero kept:
  what it is (the Oracle, operators, workers, approvals, mail, nothing

## 0.5.0

- Wake economy ([docs/NOTIFICATIONS.md](docs/NOTIFICATIONS.md#cost-model)):
  the watcher delivers one wake per observation round naming every event
  of that round, retries a refused wake at most three times, and never
  resends one that may have landed; an observation that only confirms the
  parent's own completed retire, stop, or interrupt is recorded already
  acknowledged. `ack --through <sequence>` acknowledges every pending
  event up to the highest sequence a wake or wait named.
- Cheaper polling: a working child is read every three seconds, an idle
  child every thirty, and a parent's own spawn, steer, recover, interrupt,
  stop, and retire nudge the watcher to read that child at once; settled
  children are skipped; the watcher exits fifteen minutes after the last
  child settled. A Codex wake now reads the newest turn (the oldest was
  being consulted) before choosing between steer and start.
- Cheaper reads: a long-running observer (the watcher, one `wait`) measures
  the Claude runtime once per CLI file and reads the census once per round
  (`lib/observer-cache.js`), shares one loopback connection per round for
  Codex reads, and subscribes to the app-server's notifications so an
  outstanding Codex child is read the moment the runtime reports a change.
- Claude children spawned for a parent carry session hooks (one private
  settings file per lane, passed with `--settings`) that nudge the parent's
  watcher when a turn ends, the session ends, or a notification is raised,
  so a child is read the moment it finishes instead of being polled;
  `TRANSMOGRIFY_CHILD_HOOKS=off` disables it. Verified live on the pinned
  CLI.
- Both adapters are split along their lifecycle: `lib/codex-runtime.js`,
  `lib/codex-retire.js`, and `lib/codex-recover.js` beside
  `lib/codex-adapter.js`; `lib/claude-runtime.js`, `lib/claude-spawn.js`,
  `lib/claude-retire.js`, and `lib/claude-recover.js` beside
  `lib/claude-adapter.js`. Pure moves; the adapters' public surfaces are
  unchanged. The largest lifecycle functions (Codex spawn, resume, retire,
  and recovery; Claude spawn, retire, and reconciliation; the lane CLI
  entry) are each decomposed into named phases that share one context, with
  behavior, journal phases, and error shapes unchanged.

## 0.3.1

- Turnkey child notifications ([docs/NOTIFICATIONS.md](docs/NOTIFICATIONS.md)).
  `parent-init` discovers and records how the running session can be woken
  (a Claude Code session's own Remote Control bridge, or a Codex thread from
  `CODEX_THREAD_ID` verified on the runtime by the command it is running).
  `spawn` starts a per-parent watcher (`scripts/watch.js`) that observes every
  child every few seconds and delivers a short fixed message into the
  parent's session when a child completes, needs attention, or ends; the
  message names the lane, the event kind, and the two commands to run, and
  never carries child output. Events read back carry `kind` (`progress`,
  `complete`, `attention`, `terminal`) and `terminal`; both providers report
  a finished assignment as `child.turn-completed`.
- `wait` observes every outstanding child on every call and returns old and
  new unacknowledged events together, so an old event can never hide a new
  completion; it takes `--until any|complete|terminal` and blocks up to
  thirty minutes for background use. `children --observe` refreshes every
  child's live phase and reports the watcher and wake channel.
- Claude `steer` retries transcript verification for up to 20 s within the
  command deadline before reporting `DELIVERY_UNCERTAIN`.

### Agent Operations 0.2.0 (2026-11-17)

A clean break from 0.1.x: the kit becomes rules with stable IDs, six
guides, templates for a fixed home layout, and scripts that run the
scheduled parts. See [upgrading from 0.1.x](docs/operations/architecture.md#upgrading-from-01x).

#### Rules

- **Added K-01 to K-34.** Most restate 0.1.x guidance as one rule each,
  in one place: authority and consent (K-01 to K-09), claims and outcomes
  (K-10 to K-12), structure (K-13 to K-18), review (K-19 to K-21),
  scheduled work and model runs (K-23 to K-26), hosts and effects (K-27 to
  K-29), records and privacy (K-30 to K-32), opt-in (K-33, K-34).
- **New in substance:** K-04 (no trades or money movement unless enabled
  in writing), K-16 and K-17 (one merge owner per work repository,
  shared files owner-only), K-18 (instances share no sessions), K-22
  (weekly cross-model review and the switch-in audit, on by default), K-33
  (security auto-ship as an opt-in with a recovery precondition), K-34
  (lease checks, experimental).
- **Fixed rules** (no overlay may override them): K-01, K-02, K-03, K-04,
  K-05, K-10, and K-34 once enabled.

#### Scripts

- `tick.sh`, `relay.sh`, `worker-run.sh`, `review-run.sh`, `status.sh`,
  `inbox-put.sh`, `check.sh`, `drift-check.sh` (K-23 to K-26).
- `relay.sh` sends a fixed-shape pointer to the archived notes, never the
  note text; the delivery is confirmed from the client's event stream, read
  even when the client fails; repeated failures back off and tell the
  Oracle once (K-01, K-10).
- `cross-review.sh` and the hourly hook (K-22).
- `install.sh`: `oracle`, `operator`, `skills`, `timers`, each with
  `--dry-run`; never overwrites, never edits client settings, never loads
  a timer, never uses the network.
- `check.sh kit|links|home` (K-14, K-16).
- Kernel locks, interruptible children, Claude runs in `--restricted`
  mode, every Codex tool server switched off for runs (K-25, K-27).

#### Removed

`START-HERE.md`, `VALIDATION.md`, the Python helpers, the scheduled-worker
fixture and skill, the routing sections of the worker docs, the
`operator-handoff`, `worker-profile` and instruction templates, and the
JSON machine-local profile. Their useful content moved into the rules, the
guides and the templates.

#### Known issues

- Prompts and relay messages are passed as one command-line argument:
  visible in the process list to other local users while a run lasts, and
  capped at 120000 bytes.
- Logs under the state directory grow without bound; rotate them with your
  OS tools.
- A timeout reported by coreutils `timeout` as exit 137 is reported as a
  timeout even when the cause was a manual `kill -9`.
- A registry home reached through a symlink produces a different
  transcript slug, so the watchdog reports `no-transcript` for it.
- A failed Codex run's failure note can include the start of the prompt,
  which Codex echoes to stderr.
- `cross-review.sh`, Claude-side runs, `install.sh` on a clean machine,
  systemd units and Linux are not yet proven outside the test suite (see
  the README).
- Whether `codex mcp list` reflects a project's own Codex configuration is
  unverified; runs list servers from the run's directory to cover it.
- Not yet built: the advisory pre-push guard for contributors (K-16 is
  convention plus review), `install.sh restore` (rerunning `oracle` and
  `operator` restores what is missing), and the lease, mailbox and
  takeover layer. The registry's session column gives way to the lease in
  0.2.x.

#### How the kit evolved

0.1.0 to 0.1.14 were guidance only: a growing set of documents written
after real incidents, each adding a clarification. By 0.1.14 the same
rule could appear in several places with slightly different wording, and
nothing ran on its own. 0.2 keeps the lessons and changes the shape: each
rule is stated once with an ID, the docs explain rather than legislate,
the scheduled parts are small scripts with tests, and the two clients are
peers behind one interface. Recurring findings from the weekly
cross-review are meant to become rule changes here, recorded by ID.
